# dsh-session-resume 文档系统（活文档分类账）

本文件是仓库全部文档的**单一入口与分类账**。它规定每份文档**此刻的角色**、**它属于"当前为真"还是"历史决策"**，
以及**更新它们时避免"漂移失真"的约定**（这正是本文档系统的设计目标）。

## 分层：先读哪层

- **当前为真层**——讲"此刻什么为真 + 如何复现验证"。读做开发/调试/上线都看这几份，**只信这段**。
- **历史决策层**——讲"当初为什么这样定 / 曾遇到什么坑"。翻历史用，但**不据它改新代码**；与源码冲突以源码为准。
- **已归档**——使命已完成或被取代的一次性文档，仅作定位指向，不再作为可操作正文。
- **科普层**——探讨/教学性质的通俗笔记，随认知理解而更新；不据它改代码，技术细节以 `src/` 与"当前为真层"为准。

## 写入约定（防漂移）

目标是"少失真、更持久"。遵守：

1. **不记会随时间漂移的时间戳 / 会话 / 测试数量 / 行数 / 轮次号**。要复现就用固定命令 +
   指向测试；要时序就用相对次序，不写绝对日期。
2. **当前为真层只说"此刻为真"**：一旦有 `POST /session-resume/api/*` 之类已经失效的形态出现，
   即视为**文档落后源码**，必须就地改（或标"淘汰"）。任何“待办/刷新后应…”若注定翻转，写成"如何复现验证"。
3. **传输真相固定**：本项目是 typert remote（无自建 HTTP）。写入任一文档时若见到 HTTP 路由，务必先核对
   `src/` 再做结论。
4. **进入用户的权威**：当前为真层/历史层/归档的归属变动先在本分类账更新，再改内容。
5. **单一事实源**：`src/` 是行为真相的最终裁决；文档是它的可读投影，不是反过来。

## 更新时

- 改"当前为真"文档：先改源码/测试，再同步到对应文档（未同步=文档已落后）。
- 记"新决策/坑"：无日期地补进 `WORKLOG.md` 对应主题；影响面大的节点同步进 `CHANGELOG.md` 演进史。
