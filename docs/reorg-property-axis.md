# 重组技术文档：按性质轴彻底重排（pure / io / orchestration）

> 目标：把 `src/` 从"按运行时分组（host/client/shared）"重排为"按代码性质分组（pure / io / orchestration）"。
> 判据：**复合判据（进化效率 × 可复现性 × 可验证性），见下"唯一决策指引"**——其中进化效率指一次真实改动波及面最小、纯核不被弄脏、测试回报最高、契约 seam 两端不同步的代价可见。
> 本仓 `src/` 是唯一事实源；本文档是其**可执行的重排规格与进度账**（当前为真：计划与结论）。迁移已完成并验证（124/124 测试、typecheck、build 全绿）。

> **唯一决策指引（本文档一切取舍的仲裁，最终为复合判据）**：目标函数**不是单一的 `进化效率`**，而是三条可测判据的合取——
> **① 进化效率**（改得更省、更稳、更可回退）；**② 可复现性**（结论能否不依赖偶然环境重新得到）；**③ 可验证性**（等价性能否由测试/门禁证明）。
> 一次取舍若只满足一项而不满足另两项，不算达标。由此导出三条裁决规则：
> 1. **不改无进化收益**：一次改动若没让"未来改动更便宜/更稳/更可回退"，就不做（省工序）。
> 2. **对风险三档定夺**：`已实证`照做；`低代价可实证`做一次可逆小验证再定；`加固低效`（实证成本 > 收益）直接锁定为固定点。
> 3. **typert-meta 落第 3 档→锁定固定点、永不迁**——但**因可复现性（②）而必须**配套"离开就能重新生成"的机制（`scripts/gen-typert.mjs`），使"不迁"不是"不可获得"。固定点 = 保持协议面输入原位 + 提供可复现再生，而非把它孤立。

## 0. 结论先行：一次"诚实的冲突"必须先摆到桌面上

性质轴与运行时轴（host/client）**正交**。全量 import 盘点显示：纯逻辑、副作用、编排**三者在 host/client 两侧都对称存在**（例如纯逻辑既在 `src/shared/` 又在 `src/host/resume-order.ts`；编排既在 host 门面又在 client executor）。

因此"按性质把顶级目录设为 pure/io/orchestration"**必然横穿 host/client 分界**。这有两层含义：

1. **它不推翻运行时**——契约 seam（typert）仍然存在且仍是"两端必须同步改"的唯一接缝。性质重排**不能**废弃 host/client 概念，只会把它们**降为二级维度**（每个性质目录内再按 host/client 分）。
2. **"护栏：保语义 + 测试全绿"是硬约束**——每一份迁枋步骤必须在"行为不变、测试全绿"下推进。重排只是**文件归位 + import 改写**，不是重写逻辑。

所以本方案的目标形态不是"抹掉运行时"，而是：**顶级按性质（pure / io / orchestration），契约 seam 单独成 `contract/`，运行时降为二级维度（编排内再按 host/client 分）**。这才是"性质彻底重排"与"仓真实形状"能共存的唯一写法。

## 0.1 闭环校准：三个"固定点"边界（迁移前必须先锁定）

施工前对全量 `src/` 与构建/产物映射做了对账，发现**有三处不能"照搬就迁"**，否则会破坏构建或暴露生成面：

1. **`src/typert-meta.d.ts` 锁定为固定点（复合判据裁决：保持协议面输入原位 + 提供可复现再生，见首则"唯一决策指引"第 3 条）。** 实证：`.lib/typert.host.js` / `.lib/typert.remote-client.js` 真实产物以 `Generated by @deepseek-ai/dsh-typert-generator from the Host FaceModel` 开头，且 `package.json` 的 `exports` 直指这些产物。**生成机制已明确并可复现**：`WorkspaceTypertGenerator` 只发现 `<root>/packages/*` 下、被仓根 `tsconfig.host.json` 以 project references 引用的子包；本独立单仓根不在 `packages/` 下，故就地 `npm run build` 不产 typert。**可复现再生**用影子 workspace 根（`packages/session-resume` + references 的 host/client tsconfig + 链接 node_modules），调 `scripts/gen-typert.mjs <shadowRoot>` 生成 `lib/typert.*` 并拷回（见 §3 Step 0 与 §7）。`typert-meta.d.ts` 本身保持原位：它是生成器协议面的输入，改名/移动会破坏生成与 `exports` 对齐，任何 step 不改动该文件。
2. **`tsconfig.json` rootDir=src**：所有目标都在 `src` 下，重排后 rootDir 依然成立（`lib/` 布局随之变化）。这本身不是问题，但 **`package.json` 的 `exports`/`files` 是产物路径**（`./lib/types/...`、`./lib/typert.*`、`./lib/client.js`、`./lib/types/types.js` 等）：每次重排后都必须核对 `lib/` 布局与 `exports` 不脱节。
3. **`tsdown.config.ts` 硬编码入口**：`clientBundle.entry` 指向 `src/client/index.ts`（已实证，是硬编码）。若把 client 迁到 `orchestration/client/index.ts`，必须同步改 tsdown 入口，否则 `lib/client.js` 产物代码断裂。

这三处都要在**重排第一步之前**先锁定为固定点，或单独成 step 各自验证——不能混进"按性质搬文件"的批量动作里。

## 3. 迁移队列（每步" import 改写 + 测试全绿"门禁）

**硬规则（护栏）**：
- 每步只做**文件归位 + import 路径改写**，不做逻辑改动。
- 每步结束必须 `npm run typecheck` 通过、`npm test` 全绿，才进下一步。
- 全程不改行为、不改 `exports` 面（若改了再随运行/文档一起记）。
- 禁止在一步里混入"性质拆界"（本方案基调：不中途拆，先整体迁）。

**关键施工顺序（避免本仓踩过的一个坑）**：跨目录 import 改写**必须先按"最终归宿位置"算好、再 `git mv`**，反之会因相对深度位移把引用改错。正确做法是一次性用"**最终位置**"重写全部引用（每个 import 的目标模块取其 MOVE 后的最终路径、每个文件自身也以其最终目录为基准算相对路径），然后**一次性批量 `git mv`** 落地；落地后 `typecheck` 应直接全绿，无需再逐文件补 import。切忌在部分文件已 move 后按"当前目录"去补剩余 import（那条路我已实测会产出 `../io/fs/...` 指向不存在的深度）。

按"低风险→高风险"排序，**先迁纯，再迁 IO，最后迁编排与契约面**（因为 pure 依赖最少、测试回报最高）：

### Step 0：typert 协议面（固定点 + 可复现再生）
1. **不动 `src/typert-meta.d.ts`**（固定点，见 §0.1-1）。
2. **跨目录 import 改写不只作用于 `src/`，还要覆盖 `tests/*.test.mjs`**：它们以 `../lib/client|host|shared/...` 引产物，随 src 归宿变化必须同步改写为 `../lib/orchestration/client`、`../lib/io/fs`、`../lib/pure/...` 的新路径（本仓已按该映射改完 19 个测试文件、30 处）。
3. **产物再生**：`lib/typert.*` 不在本仓 `npm run build` 内产生（生成器只发现 `packages/*` 下的工作区子包）。若被删，用 `scripts/gen-typert.mjs <shadowRoot>` 在影子工作区根再生并拷回（shadow 结构见 §7 / 脚本头注释）。
4. `tsdown.config.ts` 的 client entry 若指向被迁走的 `src/client/index.ts`，必须同步改为 `src/orchestration/client/index.ts`（§0.1-3）。

### Step 1：pure/shared 区块（把 `src/shared/*` 迁入 `pure/`）
1. `git mv src/shared/* src/pure/refs|text|plan` 对应目录（与 §3"关键施工顺序"一致：先一次性按最终位置算好全部引用，再统一 `git mv`；若跨步，则每步都按"最终位置"重写本块全部引用 + 本块文件 `git mv`）。
2. 改写所有 `'../shared/...'` 与 `'./...'` import 为最终 relative 路径。涉及：`src/index.ts`、`src/client/*`、`src/host/*`、`src/shared/*` 内部（source-ref ← session-path/url/uri）、`resume-text`←constants、`batch-text`←resume-text。**注意目标文件在 `pure/` 下的不同子目录（refs/text/plan），相对深度因最终位置而异，勿按移动前目录算。**
3. 跑 `npm run typecheck` + `npm test`，全绿才进 Step 2。

### Step 2：pure/order（达标纯核：resume-order、order-wal）
决策（复合判据，不再留分支）：**先归位、不中途拆 IO**。`resume-order.ts` / `order-wal.ts` 整体迁入 `pure/order/`，保留其中 IO 现状——不拆最"可回退、可验证"；拆 IO 属"后期可选"的拆界动作（非本场目标），按 §5 不在本迁移做。**本方案只有这一条路径，无 2a/2b 分流。**
1. `git mv src/host/{resume-order,order-wal}.ts pure/order/`（对应目标 `order.ts`/`wal.ts` 命名可保留原名以减 diff）。
2. 改写 `session-resume-service.ts` 等对 `./resume-order.js` / `./order-wal.js` 的引用，与 `order-wal` 对 `../shared/plan.js` 等跨目录引用为新的 relative 路径。
3. 跑 `npm run typecheck` + `npm test`，全绿才进 Step 3。

### Step 3：io/fs 区块（副作用）
1. `git mv src/host/{cache-root,snapshot-store,session-log,log-materialize,config,workspace,workspace-state}.ts io/fs/`。
2. 改写所有依赖这些文件的宿主 relimport（src/host/*、src/index.ts、src/io/* 相互引用）。
3. 注意 `workspace-state` 依赖 `node:child_process`（execFile），归属 io 面，不属于纯。
4. 跑 typecheck + test 全绿。

### Step 4：orchestration/host + client（编排）
1. 迁 `src/host/{session-resume-service,service,audit,resume-plan}.ts` → `orchestration/host/`。
2. 迁 `src/client/*` → `orchestration/client/`。
3. 改写 `src/index.ts` 与内外部的相对 import（`./host/...`、`./client/...` → `./orchestration/...`）。`src/index.ts` 引的 `./host/session-resume-service.js` 同步改。
4. `src/client/types.ts` **留在 `orchestration/client/` 原位**（决策：类型面不并入 contract/，保持最少动；避免为美观再拆一个类型面）。
5. 跑 typecheck + test 全绿。

### Step 5：contract/ 契约 seam（固定点先行，单独 step）
1. **`typert-meta.d.ts` 不迁**（固定点，见 §0.1-1）。本步只处理可安全迁的类型面，并**先跑一次 `npm run build` 确认 `lib/typert.*` 仍在**——若生成在改名/移后找不回来，立刻回退。
2. 迁 `src/host/types.ts` → `contract/host-types.ts`（纯类型面），并把所有 `./host/types.js` 引用改到 `./contract/host-types.js`。
3. `src/types.ts` **留在 src 根原位**（决策：不并入 contract/，保持最少动；`/types` 导出与 `lib/types/types.js` 映射因此不变）。
4. **同步关注 tsdown 硬编码**：`src/client/index.ts` 是 `tsdown.config.ts` 的 `entry`（见 §0.1-3）；若 Step 4 已把它搬到 `orchestration/client/index.ts`，本步一并核对 `npm run build:client` 生成 `lib/client.js` 正常。
5. 验证 `npm run build`（含生成器）生成的 `lib/typert.host.*` / `lib/typert.client.*` 与 `package.json` `exports` 仍对齐。契约是两端唯一共同依赖面，任何改动必须 host + client 同时同步。

### Step 6：空目录清理与全仓复检
1. 删除 `src/shared/`、`src/host/`、`src/client/` 空目录（若 host 还有 `types.ts` 保留）。
2. `git mv` 剩余 `src/` 下残余（如有）归入目标目录。
3. 跑 **全量** `npm run build` + `npm run typecheck` + `npm test`，并 trigger CI（`.github/workflows/ci.yml`）。
4. 更新 `package.json` 的 `exports`/`files`（如路径型导出）与 `docs/session-resume-architecture.md` §2.1、§4 模块职责、§5 契约——**先改源码，再改文档**，避免文档先漂。

## 4. 关键不变量（迁移前后必须一致）

1. **契约不变**：9 个 `@Remote` 端点名、参数、返回、错误语义不变（typert seam 是"两端同"的面，任何 break 都要 host/client 同步）。
2. **行为基线**：`docs/verification.md` 的固定验证命令 + 行为不变量在迁移前后 pass（订单幂等、WAL 恢复、快照保留、审计、legacy 路径修复）。
3. **类型面**：公共导出（`ResumePlan`/`ResumeConfig`/`StoredSnapshot`/`SessionInfo` 等）暴露给外部解析器/生成器路径不变或按文档同步更新。
4. **固定点（§0.1）不破坏**：`typert-meta.d.ts` 文件名与位置不变、`tsdown` entry 仍产出 `lib/client.js`、`package.json` `exports` 与 `lib/` 布局对齐。
5. **文件系统约定**：缓存根、`%TEMP%\dsh-session-resume`、物化目录布局不因迁移改变（迁移只动代码，不动物化格式）。
6. **跨运行时归档**：`src/client/` 与 `src/host/` 的运行时边界在 target tree 里以二级保留（`orchestration/host` 与 `orchestration/client`），不可把两端混进同一目录。

## 5. 回滚

- **每步独立可回滚**：每步以 `git mv` + import 改写完成，若 typecheck/test 不绿，`git checkout` 该步涉及文件即可回到上一步（step 内不改逻辑，回滚安全）。
- **物品安全**：不要在一次 step 里同时做"归位 + 契约 + 拆界"三件事；三者各自独立成 step，任一步出问题不会波及另两步。拆界（如抽 IO）为场外可选，不进入本搬迁的任一步。

## 6. 风险与反模式（诚实标注）

- **性质轴正交运行时**是最大风险源；本方案把"运行时"降为二级、契约 seam 强行单列，正是在化解它。若有人把 host/client 混到同一目录，会破坏契约两端相对相对性，且违反不变量。
- **三大高风险点（§0.1）不可混进批量搬移**：`typert-meta.d.ts`（生成面，固定点，配套可复现再生 `scripts/gen-typert.mjs`）、`tsconfig rootDir / package exports`（产物路径，迁后必须核对）、`tsdown entry`（`src/client/index.ts`，迁则同步改）。任何一步动了这三处，都必须**单独验证 `npm run build` + `build:client`**，不能只看 typecheck/test。
- **先迁移后"拆界"**是本方案基调（不中途拆），因为单纯文件归位是最可逆、最不易出错的窗口；抽 IO 等拆界是有收益但按进化效率划为场外可选，**不在本搬迁任一步里做**，避免在一场 git mv 中混入逻辑重排。
- **CI 入口**：`scripts/build.sh`/`tsconfig` 若对旧路径硬编码（include 具体文件），契约/编排迁移必须同步改；否则 `build:client`/`typecheck` 会先于测试发现。
